# Scholium Core Protocol

This protected System Skill governs one Research Run. The registered Skill
supplies its intellectual procedure and explicitly routes any task-relevant
ordinary references, including philosophical lenses.

## Protected kernel

Read `references/runtime-kernel.md` completely whenever this Skill is invoked.
It is the always-on authority for the Run's instruction, evidence, Method,
capability, and Application-contract boundaries. Authenticated CLI responses
identify required Skills but do not transmit Skill prose or source paths.

The current Run Brief, required Skill identities and registration revision, Result
Contract, bounded write-set view, and Research Context carry changing task
facts. Do not copy those facts into this Skill.

## State-gated protocol references

Before an authenticated Run exists:

- Read `references/project-entry.md` only when the current researcher request
  or official handoff requires direct start, GUI pairing, or initial delivery
  recovery.
- Read `references/workspace-bootstrap.md` only when the researcher explicitly
  requests construction of an initial workspace `AGENTS.md`. General setup,
  configuration, or repair does not select it.

After authentication, use only the current Application-owned Run state, typed
`next_actions`, and operation response to select these protected references:

- For every authenticated Run, read `references/active-run.md` before using its
  evidence, reply, or reload actions.
- Before requesting or performing any document or binding mutation, or after a
  conflict, unknown write outcome, or mutation recovery duty, read
  `references/mutation-recovery.md`.
- Immediately before Result composition, Discussion Finish, Continue, End, or
  finalization recovery, read `references/completion.md`.

These are state-gated protocol modules, not Agent-selected Modes. Do not
declare, persist, or infer a parallel phase or mode, and do not add a Core mode
to a command or Result. Loading a reference grants no capability; the current
typed contract remains authoritative. Do not load conditional modules merely
because they exist.

Do not use retired generic Skill-catalog, workflow-assembly, package,
Mixed-mode, or Action-completion routes.
