# Scholium Content Fidelity

Apply scholium-core-protocol. Fidelity is a read-only evidential function over one exact Target revision. It remains distinct from Human Review, Critique, Dialogue, and any write-capable run that requested it.

## Establish the function packet

Record the Target identity, role, fingerprint, selected checks, scope, Research Unit when present, selected Materials, available primary sources and verified passages, missing evidence, prior audit key, and stop condition.

Content is supplied by this official package. Citations may run only when Application has resolved an explicit valid Triptych binding to a researcher-owned skill declaring the required citation capability and compatible style. If none is bound, or the style does not match, report the typed repair condition; do not infer a package from its name or scan global skill directories.

## Load the method

Read references/content.md when Content is selected. Read references/citations.md when Citations is selected, then load only the exact bound citation package and conditional resources supplied by Application.

If an explicit researcher-owned Practice is selected for Content, load only its exact resource and composition rules and record the revisions. A Practice cannot replace the audit categories or evidence hierarchy.

## Execute

1. Recheck the Target and every Material fingerprint before audit.
2. If the same final fingerprint, scope, selected checks, evidence set, package revisions, and citation style already have a completed audit, return the existing outcome instead of duplicating it.
3. Classify substantive claims and evidential layers.
4. Apply Content checks against the strongest available evidence.
5. Apply Citations checks only through the resolved compatible citation method.
6. Separate source support, metadata or locator verification, and style formatting.
7. Rank findings and propose the smallest accurate correction without editing.
8. Bind the outcome to the exact fingerprint and loaded package-resource revisions.

## Return

For each requested check, report exactly one structured state: `passed`, `issues_found`, or `unavailable`. Supply a nonempty attributed summary for every outcome; `issues_found` also requires at least one nonempty finding. Record checks actually run, sources and citation method used, missing evidence or capability, required corrections, residual risk, and the staleness key. Never imply that a pending or missing audit ran automatically.
