# Bounded motion work

For terminology-only requests, use [motion vocabulary](motion-vocabulary.md)
and answer the named question without a repository survey or implementation.
For a supplied recording or component precedent, use
[precedent triage](external-motion-precedent-triage.md); media establishes visible
behavior, not source, license, accessibility, performance, or reuse rights.

Review one reachable transition under the interface skill's critique mode.
A broader survey remains read-only unless implementation is requested. Inspect
existing native/system behavior before a custom effect; absence of animation
can be the correct outcome. Apply the shared restrained-design procedure only
when a material design choice remains.

Judge object identity, purpose, interruption, reversal, cancellation, repeated
activation, focus, selection, source state, recovery, alternate input, and
reduced-motion meaning. Runtime observation supports perceived feel; measurements
support performance. Static images and code-pattern matches do not prove either.

Motion presents a change; it owns no second navigation, geometry, buffer, or
operation lifecycle. Native implementation uses the interface owner; changes
inside the editor bridge also use the editor owner. A review-and-fix request
already authorizes a bounded confirmed correction, without another approval.
Do not mechanically impose a global curve or spring on unrelated transitions;
resolve material conflicts with product authority before changing the target.

Report the named transition, evidence, smallest justified correction or no-change
finding, non-motion result, and uncertainty. A terminology, review, or precedent
request alone does not authorize source edits or dependency installation.
