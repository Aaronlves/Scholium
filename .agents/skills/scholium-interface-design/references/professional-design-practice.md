# Professional Scholium interface practice

Use this in critique, design, or decision-recording mode after the shared
restrained-design protocol has established the task, authority, solution path,
and proof boundary. This reference owns interface-specific judgment and
communication; it does not repeat the shared solution-research method.

## Inspect the task

Inspect the complete reachable task and window only as far as the named issue
requires. Trace entry, information order, action, feedback, focus,
interruption, failure, recovery, input, accessibility, adaptation, and
multiwindow behavior. Label findings as observation, researcher testimony,
canonical rule, current implementation, platform guidance, precedent, or agent
inference. A reaction is evidence of a problem, not its diagnosis.

## Judge the interface

Evaluate purpose, hierarchy, predictability, information architecture, density,
typography, composition, native fit, inclusion, scholarly trust, and tone only
where they affect the named task. Prioritize blocked or unsafe work, then
frequent-task friction, then clarity and craft. Preference alone is not a
defect.

Recommend one evident correction. Compare alternatives only when a material
semantic or structural uncertainty remains; each must change the task or
composition, not merely styling. Use the smallest faithful artifact that can
reject the decision, with realistic synthetic content and complete-window
context where hierarchy matters.

## Communicate

Lead with the recommendation, visible result, reason, important cost, evidence,
and at most one researcher-authority decision. Keep preview, visual approval,
connected implementation, automated verification, accessibility acceptance,
and release readiness separate.
