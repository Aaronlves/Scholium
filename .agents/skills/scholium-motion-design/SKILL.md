# Scholium Motion Design

Translate an ordinary description of movement into precise terminology and
evidence. This capability is read-only: it does not install, edit, build, or
implement a fix.

Apply the shared [development contract](../scholium-toolkit-maintenance/references/researcher-codex-development-contract.md).
Use product authority for meaning, Apple HIG for design claims, selected-SDK
sources for mechanics, and runtime observation for feel.

## Modes

- **Terminology:** load [motion vocabulary](references/motion-vocabulary.md),
  name the closest term, and stop unless more is requested.
- **Precedent triage:** after applying the shared method below, load the
  [external-precedent procedure](references/external-motion-precedent-triage.md)
  and return reuse, adaptation, translation, or rejection with evidence limits.
- **Review:** inspect one reachable transition and its lifecycle, alternate
  input, and reduced-motion result.
- **Survey:** map only reachable motion, purpose, ownership, accessibility, and
  measured problems; separate defects from optional opportunities.

## Method and boundaries

For every mode beyond terminology, first apply the
[restrained-design protocol](../scholium-toolkit-maintenance/references/restrained-design-and-solution-research.md).
Use its result to bind the live transition and owner. Absence of animation is a
valid outcome; stop when no decision-relevant task gap remains.

A recording establishes visible behavior, not source, license, dependency,
containment, accessibility, performance, or portability. Route later native
design or implementation to the interface owner and WebKit work to the editor
owner. Reusable motion APIs, component state, and presentation architecture
belong to interface design, not this review capability.

Judge stable object identity, purpose, entry and exit, interruption, reversal,
cancellation, repeated activation, focus, selection, source state, conflict,
recovery, alternate input, and non-motion meaning. Do not infer a defect from a
code-pattern match or infer quality from a static image.

## Report

Accept plain-language reactions; do not ask the researcher to select curves or
framework APIs. Lead with the task consequence and verdict, then state owner,
authority, evidence, smallest credible adjustment, reduced-motion result,
focused verification, and uncertainty. Require observation for feel and
measurement for performance. If implementation is also requested, continue
through the implementation owner under that existing authorization.
