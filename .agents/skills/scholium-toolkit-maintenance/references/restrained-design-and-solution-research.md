# Restrained design and established-solution research

Use before material interface, workflow, component, motion, or product-art
work. Apply proportionately: a bounded correction following a verified pattern
does not need a competitor survey.

Identify the researcher task, observed gap, controlling authority, and evidence
that would make the intervention unnecessary. Inspect the existing Scholium
owner and native solution first. For a remaining gap, compare relevant mature
precedents or libraries under the [live-source policy](live-source-research.md)
and the dependency rules in `AGENTS.md`. External precedent explains mechanisms;
it cannot authorize product behavior or replace Scholium's visual identity.

Prefer removal, clarification, reordering, reuse, adaptation, or translation
before custom behavior. Add a surface, state owner, component, Variable, or
dependency only for an unmet responsibility. Similar appearance alone does not
justify shared semantics or a reusable system.

Recommend one supported direction. Compare alternatives or prototype only to
resolve a material uncertainty; no fixed candidate count or design dossier is
required. If no concrete gap remains, explain that finding without adding work.
A restrained solution still needs complete states, accessibility, recovery,
and careful visual craft.

Briefly state the selected approach, evidence, necessary Scholium-specific
change, focused proof, and unresolved tradeoff. Reuse, adaptation, translation,
custom work, and deferral are useful distinctions, not mandatory report fields.
