# Scholium Implementation Status

**Audited:** 2026-07-21
**Target authority:** [SCHOLIUM_SPEC.md](SCHOLIUM_SPEC.md)
**Scope:** current reachability, verification evidence, migration debt, and open
acceptance only. This ledger cannot redefine the target specification.

## Reachable target behavior

| Area | Current reachable boundary |
| --- | --- |
| Triptych and storage | Multiple registered Triptychs use independently chosen Analyses, Topics, and Works; each window belongs to one Triptych. Portable control state stays beside Works in `.scholium`; machine/derived state stays in Application Support. The atomic v2 registry does not import the retired single-workspace registry. |
| Exact source | `NoteDocument`, targeted YAML edits, transactional autosave/readback, conflict handling, and traversal/symlink rejection preserve authoritative Markdown. Current roles re-encode canonically; malformed or unknown current fields fail without rewriting source. |
| Lifecycle and deletion | Create, duplicate, move/rename, Set Aside, Trash, exact-path Put Back, and permanent deletion route through `VaultRepository`. Deletion removes the note, current Critique, versions, identity, records, and affected checkpoints. A durable journal restores pre-commit state or completes post-commit privacy cleanup; concurrent path recreation is preserved for explicit recovery. |
| Move and import | Confirmed moves preflight destination and incoming-link revisions and rewrite only identically resolved links. Stable identity/records follow confirmed moves or reconciled external renames; ambiguity requires confirmation. Unclassified imports remain editable and classify into any vault. Multi-file failure rolls back revision-safe exact bytes or produces a visible external-recovery record. |
| Review and Critique | Analyses/Topics have fingerprint-bound Human Review, required concise Review Notes, drafts, and anchored Comments; no whole-note Comment fallback exists. A Work has at most one attributed current Critique under `Works/Critiques`, read-only in Scholium but externally editable. Findings bind the target fingerprint and navigate only unambiguous passages. Earlier-round chronology and Accept/Reject/Rebut dispositions remain unimplemented. |
| Research Functions | One per-window Inspector exposes Overview, Connections, and role-valid Functions. Document has no bottom Research Strip. Functions launch the existing typed panels, which fix Target and choose read-only Materials, scope, Comments, and Fidelity checks; menu/keyboard routes remain independent of Inspector visibility or mode. Dialogue is nonmutating unless promoted. Develop, Revise, Manuscript, and Critique checkpoint; Human Review and Fidelity do not. |
| Conditional methods and Fidelity | Same-run preflight persists the normal run, checkpoint, and Dialogue/Critique record; explicit resource selection may be empty without changing identities. Write runs record the exact final revision as Awaiting Fidelity and accept only a validated independent child. Direct outcomes are rejected; missing checks are Unverified; changed inputs become stale; exact evidence keys reuse committed audits without implying agent execution. |
| Recovery and chronology | Self-contained external checkpoints support ten automatic snapshots, unlimited manual retention, comparison, selective/full restore, and Finder access; pre-restore safety creation cannot evict its source. Research Record is a separate nonmodal chronology/provenance utility, never checkpoint storage. Reopen/Inspector independence and localization catalogs are automated; manual localized accessibility remains open. |
| Application and CLI | GUI and CLI share Application capabilities and trust rules. Each CLI invocation uses one snapshot runtime; existing-note mutations require current SHA-256. App/CLI import only Contracts and Application, Core remains internal, one live app runtime has one accepted event subscription, and per-window controllers own independent presentation state. |
| Connections, Search, and Attention | One workspace `GraphSnapshot` owns Vector-Link v1 resolution; neutral/transitive paths never become evidence and legacy syntax remains exact with diagnostics. Shared SQLite FTS5 covers GUI/CLI and Unicode/CJK. Attention is limited to specified structural, currency, connection, reliance, metadata, and identity conditions; dismissals are Triptych-local and deadlines machine-local. |
| Editor | CodeMirror Source/Live and sanitized Read share the checked Markdown semantic projection, bundled fonts/resources, callouts, tables, footnotes, offline KaTeX 0.18.1 mathematics, bounded previews, and semantic presentation variables; no second render authority exists. One retained Host keeps Read and one CodeMirror state mounted. The typed v3 bridge preserves exact CRLF/Unicode source, identity/generation, recovery, focus, and semantic scroll. Automated TypeScript, Swift, real-WKWebView, and isolated QA cover the implemented semantics; human visual/assistive-technology/IME acceptance, retained-memory convergence, and sustained performance remain open. |
| Properties and Zotero | Per-vault profiles control order, editable allowlists, and disclosure; `research_unit` has a role-neutral Research Status editor. Zotero is localhost-only/read-only, refuses ambiguous identity, shows only the current Analysis source or outgoing-linked Analysis sources, and offers only Open in Zotero—never attachment access. |
| Product Skills | Protected typed resources reject traversal/symlink escape; revisions cover bounded resources and assembly records only loaded conditional resources. Exactly five Workflow packages remain; Dialogue is System infrastructure and Human Review has no Skill. Source Analyzer, APA 7 verification, and Prose Control are opt-in copy-on-adoption Researcher Skills, not automatic or universal authorities. |
| Research Guidance | Compatible Triptych Skills may replace or supplement a function and contribute exact Practices through revision-checked bindings; Functions mode sees no package IDs. Citation Fidelity requires an explicit capability/style binding. Opted-in local Skills support guarded proposal, comparison, validation, attributed evaluation, atomic replacement, snapshots, and recovery; bundled packages remain immutable. |
| Dialogue and MCP | Dialogue persists per-Triptych defaults and an immutable request-time response contract: Academic Outcome is mandatory and five modules optional; Practices cannot change scope or permissions. External Zotero MCP remains separate from the built-in reader; only explicit `--probe` performs its read-only initialization lifecycle. |

## Retired reachable surfaces

- Proposal/Revision review sheets, Research Task/Session, Agent Assessment, and
  the former Agent Review surface.
- Active-note HTML/PDF export and Canvas.
- Zotero data-folder/SQLite access, additional-vault/All Notes presentation,
  and generated `_index.md`, `_agent-index.json`, or `_agent-context.json`.
- Obsolete Proposal, Research Session, workflow-bridge/readiness/lint,
  pre-release Review-store, and Add Dated Reference implementations.

Unsupported pre-release state is not read into the current interface. The
clean cutover never authorizes deleting or rewriting researcher Markdown,
unknown YAML, or unrecognized Triptych files.
