# Scholium Philosophical Practices

Treat this package as researcher-owned methodology. The researcher may edit, replace, combine, add, or retire its Practices and owns responsibility for those methodological choices.

Official Scholium Workflow Skills must remain usable without this package.

## Apply the shared foundation

Read [references/FOUNDATIONAL-DIMENSIONS.md](references/FOUNDATIONAL-DIMENSIONS.md) before applying any Practice. It defines the shared capacities; the protected Core Protocol remains the sole non-editable authority for epistemic integrity.

The four foundational dimensions are:

- Background-Grasping;
- Concept-Understanding;
- Philosophical Taste;
- Logical and Dialectical Reasoning.

These are philosophical capacities, not workflow modes or guarantees of correctness.

## Select Practices narrowly

Read only the Practices explicitly selected by the researcher or declared as optional overlays by the active Workflow Skill. The code-form names below are stable Practice IDs used by Workflow Skills and the catalog:

- `research-explorer` — [Research Explorer](references/Research-Explorer.md): discover questions, tensions, stakes, and directions;
- `historical-interpreter` — [Historical Interpreter](references/Historical-Interpreter.md): interpret texts and positions in historical and conceptual context;
- `conceptual-analyst` — [Conceptual Analyst](references/Conceptual-Analyst.md): clarify concepts, distinctions, uses, and relations;
- `argument-reconstructionist` — [Argument Reconstructionist](references/Argument-Reconstructionist.md): reconstruct reasoning while separating text from repair;
- `dialectical-partner` — [Dialectical Partner](references/Dialectical-Partner.md): develop positions through objections, replies, and costs;
- `systematizer` — [Systematizer](references/Systematizer.md): organize concepts, arguments, dependencies, and tensions;
- `thesis-architect` — [Thesis Architect](references/Thesis-Architect.md): shape thesis, contribution, burdens, and paper-level architecture;
- `philosophical-expositor` — [Philosophical Expositor](references/Philosophical-Expositor.md): make philosophical structure clear in prose;
- `reviewer` — [Reviewer](references/Reviewer.md): evaluate work across the foundational dimensions.

Do not load the entire Practice library by default.

## Compose Practices without duplication

Read [references/COMPOSITION-RULES.md](references/COMPOSITION-RULES.md) whenever more than one Practice is selected, a researcher has edited a Practice, or a Practice is intended to replace an official editable point rather than merely supplement it.

Give each selected Practice a distinct intellectual job. For example, Historical Interpreter may own contextual and textual framing, Conceptual Analyst may own the concept map, and Argument Reconstructionist may own the reasoning map.

If two Practices produce incompatible standards or recommendations:

1. preserve the disagreement;
2. identify the methodological source of the conflict;
3. explain how the choice would affect the result;
4. leave the substantive choice to the researcher.

Do not average conflicting Practices into a false consensus.

Record the selected Practice IDs and exact revisions or fingerprints in the task packet. A later edit to a Practice does not retroactively change the method used for an earlier result.

## Preserve the workflow boundary

A Practice may refine attention, procedure, or output at declared editable points. It may not:

- expand the active task scope or write set;
- grant permission;
- weaken non-fabrication or source-fidelity requirements;
- turn a proposal into researcher commitment;
- replace the active Workflow Skill's mode or output contract silently;
- function as evidence for a philosophical claim.

Report which Practices materially shaped the result. Keep the report concise unless the methodological difference itself requires researcher judgment.
