## 1. 讨论背景与问题

讨论起点为 ChatGPT 会话[构建共同知识库 platform](https://chatgpt.com/c/6a9e8931-29e4-83e9-8782-90d7bc98380a)，以及研究者提供的《Scholium_Codex_Integration_Proposal_v0.1.md》。已阅读六轮会话及独立提案全部 23 节与附录。

外部提案依据旧 REL-01 诊断，不了解当前实现。其原位讨论、来源对照、执行中介入方向具有参考价值；旧组件、三库名称、测试对象、提案审批流程与 MCP 建议不能直接沿用。后续讨论转为独立设计当前 Scholium 的应用内 Agent 协作。

核心问题是：在保持研究材料为中心的前提下，如何让哲学家与已有 Agent 在同一个工作现场持续讨论、核对、探索和修改，减少复制内容、重述指代和来回切换应用的成本？

## 2. 研究者明确表达的方向

1. **复用已有 harness。** 此前拒绝嵌入 Agent，主要是不希望自己建设 harness。接受通过运行时接口连接已有 harness，在 Scholium 内提供更紧密、更完整的交流和操作。优先考虑 Codex；不据此承诺能接管其他客户端的任意会话。
2. **自主程度由研究者选择。** 提供 Full Access、需要批准等选项，不把每次修改都强制变成提案与再次批准，也不为哲学家和 Agent 设置不必要的操作障碍。
3. **正文始终主要。** Chat 是研究材料的次级界面。可以提供专门的聊天视图，但默认布局、日常导航与操作应突出正文。
4. **左侧表达 Triptych 范围，右侧表达文档范围。** 研究者提出 Chat 放左侧，并据此考虑将 Outline 移到右侧。具体布局仍需确定与验证。
5. **减少通过文件树的中转。** Chat 中提到的真实文件可以直接打开；需要目录上下文或自由浏览时再切换到文件树。
6. **继续探索正文编辑辅助。** 研究者提出相关笔记推荐，并询问其他直接帮助哲学思考和写作的功能；具体功能与顺序尚未批准。

权限选项不能被曲解为忽略保存、并发编辑、身份、版本与恢复。它们控制 Agent 的行动自主程度；文档操作仍需准确可靠。

## 3. 正在收敛的空间与导航方案

| 区域 | 建议职责 | 变化依据 |
| --- | --- | --- |
| 左栏 | Library／Chat 切换；三库导航、检索、会话访问 | 当前 Triptych；切换 Note 不自动切换会话 |
| 中央 | 正文阅读与编辑、材料定位与必要对照 | 研究者主动打开的文档或材料 |
| 右栏 | Outline／About／Links | 当前文档；Outline 的统计随其迁移 |

以上是讨论中的布局方案，不是已批准的界面规范。Library、会话列表和完整聊天不应上下堆叠成多个狭窄区域；Chat 内可通过当前会话选择器进入历史。两种左栏呈现保留各自输入、滚动与选择状态。

具体导航意图：

- 点击可解析的 Chat 文件引用，在中央打开或选中已有文档；有可靠段落定位时一并定位，左栏保持 Chat。
- “在 Library 中显示”才切换到文件树、展开目录并选中文件。
- Library 文件和正文选区都能加入当前会话。加入材料是准备输入，不自动发送请求。
- 引用绑定文档身份与必要版本，不能把模型生成的任意文件名伪装成已解析链接。找不到或存在歧义时保留查找与说明路径。
- 新回答不自动展开 Chat，不抢焦点或滚动位置。专门会话视图是同一会话的另一种呈现，不复制会话、权限或正文状态。

需要通过原型判断：Chat 阅读宽度与正文空间；左栏切换时文件浏览的便利性；右栏三个功能的发现性；窄窗口、键盘与辅助功能路径。

## 4. 会话、运行与权限：候选组织方式

这些是 Agent 提出的实现方向，研究者尚未逐条决定。

- 会话属于一个 Triptych，围绕持续的研究意图，可引用多篇 Analyses、Topics、Works，也可从没有关联 Note 的问题开始。不要求一 Note 一会话或全库共用一条无限会话。
- 第一条消息开始会话，不强制创建研究问题卡片、填写阶段、完成目标或维护 Records。
- 会话与一次活动执行分开。一次回答结束不等于会话结束；归档不代表哲学结论获得认可。
- 提供恢复、搜索、重命名、固定、归档；探索明显分叉时另开讨论。会话分支不复制正式正文、不自动合并结论。删除会话不撤销正文修改或删除独立恢复证据。
- 读取范围、实际读取材料、当前消息引用对象分别呈现。旧消息绑定当时快照，新读取明确使用当前版本。
- 权限策略尽量复用运行时的实际能力，用户选择默认值并可按会话调整。不在每轮重置，也不另外构建重复审批系统。具体名称、默认值、范围、继承与切换语义待确认。
- 运行时拥有 Agent 执行循环及其认证、执行历史；Scholium 拥有文档现场、会话关联和必要呈现。公开历史投影、未发送输入与恢复状态需要明确唯一所有者和持久性，不直接读写运行时私有数据库。
- 提供执行中补充意见、请求输入、停止与重连。显示可由事件证明的操作，不把“已接收”描述成理解正确。
- 停止阻止新操作进入，并核对已经进入提交的操作；不伪装成回滚。结果不确定时核查而非盲目重试。
- 会话关闭、窗口关闭、应用退出、睡眠和重启的区别需明确，不默认承诺隐藏守护执行或跨设备会话同步。

## 5. 候选功能与研究价值

### 5.1 协作基础与文档连接

| 功能 | 目的与边界 |
| --- | --- |
| 选区、Note、多份材料加入会话 | 准确交接当前对象，包括未保存文字；发送前可检查 |
| 引用原文、用户消息或 Agent 回答继续交流 | 保留明确指代与版本；追问不丢失对象 |
| Agent 准备定位或对照请求 | 研究者打开后展示材料；不任意控制界面或抢焦点 |
| 材料清单与阅读范围 | 区分可访问、已读取、当前引用；缺失与部分读取保持可见 |
| 材料变化提示 | 保留旧引用，提供当前版本与差异；不自动将旧判断判为错误 |
| 会话访问现有变更检查 | 打开正文、准确比较、符合条件的 Undo；复用 Agent Changes |
| 将选定讨论整合进已有 Note | 先读目标再整合；按用户权限预览或执行，不机械追加聊天 |
| 从 Note 找回有关会话 | 根据明确引用和实际操作关联，不把词语相似当成研究关系 |
| 持续会话、探索分支与运行控制 | 保存输入、继续同一问题、介入执行和恢复；减少管理负担 |
| 模型、运行时、权限和方法入口 | 渐进显示实际能力，避免配置占据正文 |

### 5.2 直接帮助哲学研究的交互

最高优先的价值假设是共同检查依据、持续处理实质分歧、将获得的理解落实到现有研究。其他能力是否值得建设，应以实际使用验证，而非功能数量判断。

- **来源对照：** 可展开上下文并加入相反材料，区分原文、Analysis 重构、Agent 判断和研究者承诺；真实引文不自动构成支持。
- **针对具体判断往返：** 指向概念、前提、推论或限定提出异议；检查回应是否真正处理该异议，而不是仅改写语气。
- **整合到现有论证：** 说明哪些判断改变、哪些保留、影响哪一步；不自动将探索性假设提升为立场。
- **共同补全论证：** 明确已有前提与 Agent 补充的前提，允许研究者拒绝补充并继续检验。
- **临时改变假设：** 固定其他条件，检查局部变化的后果；不自动修改正式立场。
- **寻找判别性材料：** 明确什么证据能区分竞争解释，再寻找材料；允许材料仍不足以区分。
- **跨作者概念比较：** 比较术语在各自论证中的作用、对立项和可推出的结论；每项归属可返回来源。
- **有针对性的追问：** 帮助研究者澄清尚未成形的直觉，每次提出有推进作用的问题，不强制问卷。
- **独立分析后对照：** 用户可暂不展开 Agent 回答，完成自己的判断后比较依据与分歧。
- **指定立场下的异议：** 在明确前提与反对范围内持续检验，不为了批评不断更换立场。

以上多属 Agent 方法与交互能力，并不要求为每项活动建立独立模块、固定卡片结构或新知识类型。研究者的术语约定与对原文的事实纠正应区别处理：前者指导当前讨论，后者仍需核查，Agent 可以提出有依据的反对。

### 5.3 正文编辑辅助

| 候选功能 | 预期用途 |
| --- | --- |
| 段落级相关笔记推荐 | 返回具体片段及推荐依据；支持预览、并排阅读、链接或讨论 |
| 为判断找依据或反例 | 由明确选区和问题驱动，说明支持范围与未找到的边界 |
| 原位编辑指令 | 从选区表达修改意图；短操作就地完成，复杂往返进入同一 Chat |
| 引文与引用插入 | 区分直接引文、转述、Note 链接，不补造未知出处 |
| 术语用法对照 | 比较本文与指定笔记的实际用法；不同用法不自动等于错误 |
| 判断与上下文衔接检查 | 检查前提、结论范围、问题转换、重复内容，并指向具体位置 |
| 局部段落重组 | 比较组织方式，明确移动、删减与新增是否改变论证关系 |
| 与段落关联的待查意见 | 可立即交给 Agent 或之后继续；长期保留使用明确的 Markdown 表达 |
| 修改后的局部影响检查 | 找出可能仍依赖旧定义或前提的段落；作为复查建议而非自动裁决 |

相关笔记推荐位于右侧文档辅助范围，可主动触发，也可考虑用户开启的自动辅助。结果必须与 authored Links 区分。词汇命中、已有链接和 Agent 阅读后的解释分别说明；不把检索分数包装成哲学相关性、支持或反驳。

正文不能长期铺满标记或被逐键弹窗打断。短操作靠近选区，材料与检查结果使用右侧或中央阅读区域，持续交流使用左侧 Chat。

## 6. 当前基础与不能直接沿用的旧方案

以本次读取的规范与代码为基础，不代表运行或发布验收：

- 已有固定七工具的本地 MCP、运行中 App 的路由、当前编辑器协调、Note 指纹校验、修改证据与有条件的 Undo。应复用这些所有者，不平行重建知识服务。
- 现行规范将会话和运行交给外部宿主，排除内嵌运行管理与第二审批层。应用内会话与新的权限选择需要正式修改相关目标，不能描述成普通适配器增量。
- 当前左栏为 Triptych／Outline，右栏为 About／Links；移动 Outline 与加入 Chat 是明确的界面与状态归属变化。
- Settle 是研究者对已保存版本的稳定性判断；写入、看过变化、会话结束均不自动构成 Settle。
- 来源 Note、论文全文、Zotero 元数据与附件需要各自的真实读取路径，不能把已有 Note MCP 当作完整论文读取服务。
- 测试使用 [标准 TestVaults](../../TestVaults/README.md) 的隔离副本；旧提案中的 Dialogue／Comments／Checkpoints 测试集不是当前基线。

## 7. 第一项实现建议：正文与 Codex 的完整会话闭环

**状态：Agent 建议，待研究者决定；本轮未开始实现。**

建议第一个可交付切片是：在真实文档旁开启并继续 Codex 会话，能够准确交接选区、读取并打开相关 Note，并按用户选择的权限完成一次单 Note 修改。优先验证紧密协作的共同基础；不以推荐系统或独立的空聊天壳作为第一项交付。

### 7.1 先验证阻断性运行时能力

在仓库 `.build/` 下使用合成材料和隔离状态，指定一个官方运行时测试版本，验证连接与认证、会话往返、MCP 工具调用、活动执行补充输入、停止、恢复，以及 Full Access／需要批准策略的实际含义。检查工具请求如何关联当前会话与 Scholium Triptych、审批是否可直接复用、现有 MCP 是否会绕过所展示的策略。

这是接入实现的前置验证，不是产品交付，也不授权使用私人研究库。若实际能力与需求不符，先报告差距，不用自建完整 harness 或放宽全部限制掩盖。

### 7.2 第一个用户可用切片

1. 一种运行时：Codex；一个明确 Triptych 下的可持续会话，保留基本历史访问和重开能力。
2. 左侧 Library／Chat 及右侧 Outline／About／Links 的选定布局；实现前确认相关规范变化。
3. 当前正文选区加入会话，交接精确文本、身份及版本，不因切换 Note 隐式改换会话目标。
4. 接收回答、继续追问、在执行中补充意见；流式结果不阻塞编辑、抢焦点或滚动。
5. 复用现有 Note 检索与读取；Chat 的已解析引用在中央打开，并可在 Library 中定位。
6. 用户可选择经验证的权限策略。完成一次获准的单 Note 修改，保留现有版本、保存、比较与 Undo 路径；不引入强制 Proposal 生命周期。
7. 停止、连接失败、待输入、重连与会话重开有准确语义，未发送内容和不确定操作不会静默丢失或重放。

界面布局、运行时与文档操作需要作为一个完整切片收敛；不是先改造整个应用导航，再等待 Agent 能力接入。

### 7.3 第一片的验收场景

在隔离的标准 Triptych 中，从 Work 选取一段文字开始讨论；Agent 检索并读取一篇 Analysis，返回可打开的引用；研究者在中央阅读并编辑，继续向同一会话补充意见；按所选权限修改一个指定 Note，并能核对实际变化。另行验证修改期间的源版本变化、停止与结果不确定、断线重开、未保存输入，以及键盘与窄窗口使用。

运行结束、文字进入缓冲区、磁盘保存成功分别报告真实事实；已经确认的写入不能因通信失败而重复执行。验收比较对象为当前 Scholium＋外部 Codex，而非仅普通 Markdown 编辑器。

### 7.4 后续顺序建议

第一片可用后，优先深化引用回应与原文对照，再验证段落级相关笔记推荐和原位编辑辅助。多运行时、复杂分支、跨文件成组修改、广泛自动推荐和研究管理面板不作为第一片前提。

## 8. 下一步仍需决定

- 是否接受第 7 节的第一片范围，以及左右栏布局是否正式进入规范。
- 运行时支持的真实权限档位、默认值、会话继承、切换与现有 MCP 审批的关系。
- 第一片怎样访问会话历史，以及会话、窗口、进程退出后的生命周期。
- 后续原文对照首先支持哪些来源获取方式；不得把 Note 分析当作论文原文。
- 推荐与正文辅助采用手动触发还是用户开启的持续模式、展示位置及其与 authored Links 的关系。

这些待决定项不构成本轮必须回答的问题；记录完成后继续讨论第一步，不据此启动代码修改。
